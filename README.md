# 分拣过机台（Sortbay）

骨架：过机扫描装载 → 口门路由裁决 → 错分回流批次 → 封袋班次对账

- 前端 http://127.0.0.1:6600
- API http://127.0.0.1:11600

## 封班写闸（全局唯一口径：多路拒写可重放为准）

封班成功后，**所有会改本班账的写入口全部关闭**，不引入世代号续作、不与「冻结游标但放行收口」口径混用。
**封班回执成功 ⇔ 五路写口全部被拒，且该结论能由闸事件流重放复现；任一路仍可写则整笔回滚封班宣称。**
不允许只改封班页大字、或用 `surface_ok` 之类的伪值收口。

| 闸 | 写口 | 封班后 |
| --- | --- | --- |
| 装载闸 | `POST /api/扫描`（过机装载） | 拒绝（409），皮带不收新件 |
| 裁决闸 | `POST /api/扫描/{id}/路由` | 拒绝（409） |
| 回流闸 | `POST /api/回流批次`（错分回流） | 拒绝（409） |
| 集包闸 | `POST /api/封袋/开袋`（开新袋） | 拒绝（409），封后禁开新袋 |
| 封袋闸 | `POST /api/封袋/{id}/入袋`、`/封口` | 拒绝（409） |

只读面（总览、扫描册、口门页、班次页/对账、封袋、回流、路由表、审计）封班后照常可用。

### 判定权威与可重放

- 权威来源是 `shift_gate_events` 事件流：封班一次写五条「关」事件，`shifts.sealed` 是同事务物化的快照。
- 闸态由 `replay_gates()` 重放事件流得到；`GET /api/审计/闸事件/{shift_id}` 返回原始事件流、重放结果、逐路拒证与「重放与快照一致」校验。
- 封班回执（`GET /api/班次/对账` 的 `封班回执`）逐路给出写口判决；`GET /api/总览/探针` 用同一判定函数核对当前写口，杜绝回执与写口各说各话。
- 撕裂显式暴露：`封班撕裂` 表示「sealed 快照」与「事件流重放全关」不同命；总览/对账/审计/班次列同刷该字段，页面以拒证为准，不得显示「已封可办」。
- 每个写口按**实体所属班次**判闸（路由/回流看扫描件的 `shift_id`，封袋看袋的 `shift_id`），不随「当前班次」漂移。

### 并发与半截写

- 所有写口走 `db_write()`：进入即 `BEGIN IMMEDIATE` 拿写锁，判闸在持锁后执行，封班与装载等写事务在 SQLite 层串行化。
- 封班与写口在同一事务内同刷（班次标志 + 五闸事件 + 自证 + 审计），任一步失败整体回滚，不存在半截封班或绕过闸的半截写。
- 封班前置：无未路由/未封袋件、无集包中袋；不满足则 400 且不留任何闸事件。

## 测试

```bash
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
```

夹具（`backend/tests/`）覆盖：封后仍装载/裁决/回流/集包/封袋、未封误挡、封班前置失败无半截、写事务回滚后闸态与写范围不拧花、写锁内复查闸态、封班与装载/过机并发（无幽灵扫描行）、五路拒证可重放、正向/反向撕裂暴露、条码目的地与分拣线路由审计同命、并发读者同刷。
